Registry, schema/provider contract, local planner, pure layout resolver, authored visuals, DOM fitting and export have separate responsibilities. No generic editor framework, executable model markup, unrestricted user SVG, external image API or replacement renderer was introduced.

## Typography, copy hierarchy and fitting

V3 uses display fonts only where suitable, with Inter 400/600/700 supporting roles. `fontSynthesis:none` prevents synthetic display bolding. The verified font bundle is SHA-256 checked, relevant faces are explicitly loaded, and measurement waits for readiness. Font failure marks `FONT_UNAVAILABLE` and blocks v3 exports rather than silently accepting substitution. Unsupported code points have a visible system-font warning. Legacy fonts/options are unchanged.

Short, positively identified local event subjects can become concise headlines while the complete supplied statement moves to supporting copy: **“A robotics workshop for students.” → “Robotics workshop”**, with the full audience-bearing sentence preserved below it. Legitimate negative statements are not shortened by that rule. Recognized missing-input/no-invention instructions stay in interpretation metadata and warnings; genuinely subjectless briefs still return honest incomplete-input behavior before provider dispatch.

Complete supporting clauses form groups without dropping facts. Date/time and venue groups have stronger weight/rules; entry facts have secondary emphasis; registration URLs span a grid row with authored break opportunities and unchanged characters. Mixed clauses retain their original wording; the engine does not extract invented labels or redesign every sentence semantically. Swiss column graphics received more allocation. All supplied facts, CTAs and supporting text survive platform adaptation and bounded correction.

Two-axis DOM fitting checks scroll width/height, native bounds, role floors, basic contrast and unintended content/art intersections. At most three deterministic passes use the original layout, remove art/expand text, then allocate more support space and a bounded lower headline floor. Corrections/sizes/issues are inspectable. No silent truncation or dropped CTA/support is permitted; unresolved defects refuse the affected export.

Native role heuristics are headline 64 wide / 76 square / 80 portrait, dense 56 wide / 64 tall, final correction floor 48; support 30 wide / 32 tall; kicker 26; CTA 30 wide / 32 tall. These are internal readability heuristics, not official challenge requirements or proof of social-scale readability. Fonts, content density and actual display size still matter.
