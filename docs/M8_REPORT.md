## Implemented editor

The existing canonical v3 renderer, native formats and validated specification remain authoritative. Optional `editing.version=1` adds bounded properties for existing kicker, headline, support, CTA, illustration/image and eligible anchor regions. No arbitrary HTML/CSS/SVG, alternate canvas renderer, raster-only text editor, new font or external asset.

- **Direct selection and positioning:** enable Edit elements, select the visible handle, drag and release to apply. Handles are siblings outside the canonical export node. Drag preview is a non-authoritative outline; one validated revision is committed on release. Pointer cancellation discards it.
- **Resize:** a visible corner handle applies bounded width/height multipliers; numeric controls provide keyboard alternatives. Regions remain inside native canvas bounds. Movement is bounded to +/-25% per axis; size multipliers 0.5–1.5. Bounds constrain geometry, not artistic merit.
- **Typography:** existing approved taste fonts stay intact. Controls adjust text alignment, native tracking (-3 to 6 px), line height (1–1.6) and fitted size ceiling (0.8–1.2). Readability floors are unchanged, and text can still be refused. Word-block headline leading follows the override too. These are bounded overrides, not arbitrary font styling.
- **Scope:** shared campaign adjustments and individual format overrides are clearly selectable; per-format properties take precedence. Image crop/zoom/fit/framing and its format placements remain functional. Selecting an absent element does not create new artwork.
- **Layers:** supported elements can change order; illustrations alone can be hidden. Public text and factual anchors cannot be hidden. A higher layer never bypasses overlap/obstruction checks.
- **History:** Undo/Redo buttons and Ctrl/Cmd-Z, Shift-Z or Ctrl-Y outside typing fields restore applied copy, style, image and layout changes. Up to 30 snapshots, one current committed state, monotonic revisions. Native input undo is retained while typing. New generation/project restoration starts a fresh history.
- **Reset:** generated composition restores its original direction/geometry/typography/palette/image base while preserving applied public copy. Undo can restore the previous manual composition.

Every commit remeasures fonts, facts, fitting, bounds, overlap and contrast. Export locks and pending-generation guards remain. Invalid/overlapping manual changes are not silently published; affected PNG/HTML export is refused with existing explanations. Inspectable/downloadable JSON contains the same applied specification. Legacy v1/v2 and v3 without editing keep their old path. No full arbitrary-layer authoring or unconstrained design-editor framework is claimed.

## Local Projects

Native **IndexedDB** was selected for transactional, asynchronous storage of image-bearing snapshots. No synchronous localStorage writes, external service, account, authentication or dependency was added. Projects stay on the current browser **and origin**; changing hostname/origin will not automatically migrate them.

The Local projects dialog supports explicit save, reopen after reload, rename, independent duplicate and confirmed deletion. Records carry a versioned validated specification, original generated reset base, committed input, truthful generation metadata, timestamps, revision and optional thumbnail. Thumbnail generation reuses the exact existing native PNG export function and downsamples its valid portrait result; it is not a second artwork renderer. If a thumbnail cannot be prepared, a labelled campaign summary is available. Private raster layers and per-format overrides survive restoration exactly; resource hashes/fonts/geometry are checked again before export readiness.

Writes resolve after transaction completion, not request success. Saved revision is checked within the write transaction; stale overwrites refuse instead of replacing another tab's saved work. Failed/quota-refused writes preserve the previous saved version and current workspace. Bounds: 50 projects and 1.2 MB serialized record, with a bounded JPEG thumbnail. No automatic eviction. Unknown/corrupt records are ignored and preserved while valid projects stay accessible. Unsupported database/storage access is reported. Unknown credential/configuration fields are rejected by strict record schemas; the project path never reads server keys, browser authentication storage or provider configuration.

Saving is manual; unsaved changes and undo history are not automatically persisted. Project data is not encrypted or isolated from scripts running on this same origin. Clearing site data/private browsing/browser eviction can remove it. JSON/HTML downloads are manual portable backups; project-file import and cross-device/cloud restoration are not implemented. No simulated cloud, collaboration or social publishing is exposed. Opening another project asks before replacing an existing workspace; deleting requires explicit confirmation.
